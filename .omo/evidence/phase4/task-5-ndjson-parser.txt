Task 5: NDJSON progress parser — Evidence
==========================================

Date: Thu May 07 2026

Files Modified
--------------
1. gui/electron/cli-args.ts
   - Always appends `--progress-format json` at the end of buildCliArgs.

2. gui/electron/progress-parser.ts
   - Kept ProgressLineBuffer (unchanged behavior).
   - Marked legacy parseProgressLine() as @deprecated (kept for back-compat).
   - Added ProgressEvent discriminated union type covering:
       started | frame_started | frame_written | banner | error | complete
   - Added parseNdjsonLine(): tries JSON.parse, validates `event` is a string,
     returns null on any failure (non-JSON lines are caller's responsibility).

3. gui/electron/ipc-channels.ts
   - Added PROCESS_FRAME_WRITTEN ('process:frame-written')
   - Added PROCESS_BANNER ('process:banner')

4. gui/src/ipc/channels.ts
   - Mirrored PROCESS_FRAME_WRITTEN and PROCESS_BANNER.

5. gui/electron/main.ts
   - Swapped import: parseProgressLine -> parseNdjsonLine.
   - Rewrote stdout lineBuffer.onLine to switch on event.event:
       started        -> PROCESS_PROGRESS { current: 0, total }
       frame_started  -> PROCESS_PROGRESS { current: n, total }
       frame_written  -> PROCESS_FRAME_WRITTEN { path, n }
       banner         -> PROCESS_BANNER (full payload)
       complete       -> PROCESS_PROGRESS { current: total, total } (final 100%)
       error          -> PROCESS_ERROR (event.message)
   - Non-JSON stdout lines fall through to PROCESS_LOG (preserves old logging).
   - PROCESS_COMPLETE is still fired by the proc 'exit' handler (not changed).
   - frame:latest IPC handler retained as a fallback (not deleted).

6. gui/electron/preload.ts
   - Added contextBridge methods:
       onFrameWritten(callback) -> unsubscribe
       onBanner(callback)       -> unsubscribe
   - Both follow the existing handler-add / removeListener pattern.

7. gui/src/types/window.d.ts
   - Added onFrameWritten and onBanner declarations on DlssApi interface to
     match preload.ts exactly.

8. gui/src/hooks/useProcessing.ts
   - Added BannerInfo type and exported from module.
   - Added latestFramePath (string | null) and banner (BannerInfo | null) state.
   - Registered onFrameWritten + onBanner listeners in the existing useEffect.
   - start() resets latestFramePath to null on each new run.
   - Returns latestFramePath and banner from the hook.

9. gui/src/components/ProcessingView.tsx
   - REMOVED the previewTimerRef + 3-second polling useEffect that called
     window.dlssApi.getLatestFrame.
   - REMOVED local latestFramePath state — now consumed from useProcessing.
   - Adjusted title prop to use `latestFramePath ?? undefined` for new
     (string | null) type.
   - Removed setLatestFramePath('') from handleStart (hook resets it now).

Backward-Compat Notes
---------------------
- parseProgressLine and frame:latest IPC are retained per task spec.
- Non-JSON stdout still routes to PROCESS_LOG so older binaries (without
  --progress-format support) still surface their stdout in the log pane,
  though progress display will not update for them. New CLI in JSON mode is
  the authoritative source going forward.
