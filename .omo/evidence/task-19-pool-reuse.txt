Pool reuse semantic verification (logic walkthrough)
--------------------------------------------------------------------------------
TexturePool::acquire(desc):
    PoolKey k = makeKey(desc);
    if (m_free[k] not empty):
        h = m_free[k].pop_back();
        ++m_hitCount;
        return h;                 // <- SAME VkImage returned
    return allocateNew(desc);     // <- only when no match in pool

TexturePool::release(handle):
    m_free[makeKey(handle->desc)].push_back(handle);
    while (m_totalBytes > m_budgetBytes) evictLRU();

This corresponds to the QA assertions in the task brief:
    "acquire(1920x1080 R16F) + release + acquire(same) => same VkImage"
    "acquire(R16F) + release, then acquire(R32F) => different VkImage"
    "10 uploads -> exactly 1 vkQueueSubmit call"
    "if budget exceeded, oldest freed texture is destroyed"

UploadBatch::submit() (annotated)
--------------------------------------------------------------------------------
   1. Allocate one staging VmaBuffer per pending upload, memcpy CPU data in.
   2. createTransferCommandPool(); allocate ONE command buffer.
   3. Begin command buffer.
   4. For each upload:
        - vkCmdPipelineBarrier2  (UNDEFINED -> TRANSFER_DST_OPTIMAL)
        - vkCmdCopyBufferToImage
        - vkCmdPipelineBarrier2  (TRANSFER_DST -> finalLayout, COMPUTE_SHADER read)
   5. End command buffer.
   6. >>> vkQueueSubmit(queue, 1, &submitInfo, VK_NULL_HANDLE) <<< -- exactly ONE
   7. vkQueueWaitIdle(queue) (so staging can be safely freed).
   8. Free command buffer + pool, freeStagingAll(), clear m_uploads.

This satisfies the v2 design intent of replacing v1's per-upload submit storm
with a single batched submit per frame.
